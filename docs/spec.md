## 0. 导言

### 0.1 configer 是什么

configer 是一个桌面 GUI 配置文件编辑器，也可以被其他程序以子进程方式调用：

```
configer open <file> [<file> ...]
```

它面向的真实场景（见 §0.4 金样本）：机器人项目里既有「Python 模块级大写常量」当配置用（`param.py`），又有 ROS 2 的深层嵌套 YAML 参数文件（`config.yaml`）。这些文件由人手工编辑、由程序直接读取，**不存在也不会存在统一的文件格式**——ROS 2 只吃 YAML，Python 项目用模块常量。因此 configer 规范的对象不是"文件格式"，而是 configer 内部的**语义模型**；每种文件格式由一个**适配器（adapter）**负责解析与写回。

四条核心理念，全文所有规则都必须服务于它们：

1. **不存在统一文件格式**：核心是语义模型，格式是适配器的私事。
2. **无损写回是生死线**：验收标准是"用户改一个值，提交落盘后 `git diff` 只出现那一行"。核心必须做保留格式（round-trip / CST 级）的编辑，未编辑行字节级不变。
3. **注释即文档**：从注释中提取说明与约束，把人类已有的人肉约定代码化，对老文件零迁移成本。结构化标注只是可选增强（§6）。
4. **推测不作铁律**：从注释启发式**推测**出的约束只产生黄色警告（照常提交落盘并持续黄标）；只有**显式声明**（@ 标注）的约束才红色拦截、不落盘。

### 0.2 读者与范围

本文面向未来的实现者（可能是不熟悉本项目讨论过程的工程师或 AI agent）。文档必须自洽：不读任何外部资料也能照此实现 v1。实现语言不在本规范强制范围内；GUI 技术栈已于 2026-09-08 决议为 NiceGUI 双模式，UI 布局与编辑模型亦已决议为 IDE 形态多文件侧栏与实时落盘，其余开放设计点已于 v0.4 全部决议（见 §10、§7、附录 B），但**接口语义、校验语义、写回保真语义是规范性（normative）的**。

关键词约定（RFC 2119 风格）：**必须** / **不得** = 强制；**应当** = 强烈建议，偏离需说明理由；**可以** = 可选。

### 0.3 术语表

| 术语 | 含义 |
|---|---|
| 语义模型 | configer 内部对"一份配置里有哪些可调项、各自类型/取值/说明/约束"的结构化表示（§3） |
| 适配器 adapter | 一种文件格式的加载器 + 写回器，实现 §4.1 接口 |
| 条目 item | 语义模型中的一个可配置项（对应 YAML 叶子标量或 Python 模块级常量） |
| 字面量 literal | 条目在源文件中的原始文本 token，如 `100.`、`"adult_size"`、`True`、`-6.5` |
| 字面量风格 | 字面量的书写形式而非数值：尾点、尾零、布尔大小写、引号风格、对齐空格等 |
| CST | 具体语法树（保留注释/空行/空白等全部源文本细节的语法树） |
| 注释画像 comment profile | 某适配器对"注释如何变成说明/约束"的解析约定（§5） |
| provenance | 一条说明/约束/类型的来源：`declared`（显式 @ 标注）/ `inferred`（注释推测）/ `comment`（注释原文）/ `none` |
| dormant | 休眠条目：作者声明当前不生效的配置（如 param.py 的“休眠配置:”节）；v0.4 起允许编辑并实时落盘，UI 黄标提示“当前不生效（休眠配置）”（§10 U-8） |
| 提交 commit | 编辑从内存暂态正式落盘的动作（§7.5）。v0.3 起不存在"保存"动作，流程性语境一律称"提交/落盘" |
| 未提交暂态 | 用户已输入但尚未提交的值；类型/declared 违规的暂态不落盘（§7.5） |
| 金样本 | §0.4 列出的两份真实文件，所有示例与验收测试取材于此 |

## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 可判定含义 |
|---|---|---|
| G-1 | 跨语言零集成成本的配置 GUI 编辑 | 被编辑程序**不需要**任何改造：不引入 SDK、不改代码格式。configer 直接读写既有 param.py / config.yaml |
| G-2 | 无损写回 | 见 §7：未编辑行字节级不变；编辑行只替换值 token；金样本恒等往返字节一致 |
| G-3 | 注释即文档 | 注释中的说明与约束被解析进语义模型并完整展示（§5）；对没有任何标注的老文件零迁移成本即可用 |
| G-4 | 校验与防呆 | 类型硬校验；declared 约束拦截、inferred 约束黄色警告（§7.5、§8）；外部修改检测防覆盖（§7.6） |

### 1.2 非目标（v1 明确不做）

以下事项 v1 **不做**；在本规范语境下提出即视为超范围：

1. **格式互转**：不做 YAML→TOML→Python 任何形式的转换。
2. **配置版本管理 / 远程同步**：不做 diff 历史、不做云端；版本管理交给 git。
3. **进程内嵌 UI 库**：configer 不作为库嵌入宿主进程提供 UI；集成方式只有子进程 CLI（§9.3）。
4. **解析或执行 Python 代码**：Python 适配器**不得** import 目标文件、**不得**求值表达式。param.py 金样本中的 `math.radians(15)`、tuple 表、函数定义一律按只读文本处理。
5. **跨字段耦合校验**：不做"ENTER < EXIT""哨兵值成对修改"这类跨条目校验（param.py 中 `KICK_ENTER_M < KICK_EXIT_M`、`X_OUR_KICKOFF_TARGET` 与 `Y_OUR_KICKOFF_TARGET` 成对属于此类）。单条目内的类型/枚举/范围校验属于目标 G-4。
6. **数组 / 元组 / 嵌套表的编辑**（v2）：param.py 的 `KICK_POWER_BY_X` 表、config.yaml 中若出现序列，v1 一律只读展示或不展示（§4.3 R-5、§4.4 Y-6）。
7. **移动端**：不做移动端；"远程改配置"场景由 GUI 浏览器模式覆盖（附录 B 已决议项）。

## 2. 三层架构总览

```
┌──────────────────────────────────────────────────────────────┐
│                            前端层                            │
│ GUI（NiceGUI，浏览器 / native 双模式）                       │
│   侧栏多文件 / 条目列表 / 详情面板                           │
│ CLI                                                          │
│   configer open <file>...                                    │
└───────────────────────────────┬──────────────────────────────┘
                                │ 稳定接口：ConfigDoc / EditOp / Diagnostic
┌───────────────────────────────▼──────────────────────────────┐
│                         核心语义模型                         │
│ ConfigItem / ConfigDoc / Constraint / Diagnostic / EditOp    │
│ 校验引擎：declared 违规→拦截；inferred 违规→黄色警告         │
│ 写回引擎：提交门控 / 原子写 / 外部修改检测（基线哈希）       │
└──────────────┬────────────────────────────────┬──────────────┘
               │ Adapter 接口                   │ Adapter 接口
┌──────────────▼──────────────┐  ┌──────────────▼──────────────┐
│ Python 适配器（v1）         │  │ YAML 适配器（v1）           │
│ libcst（CST 级编辑）        │  │ ruamel.yaml round-trip 模式 │
│ 画像：作用/影响/建议、      │  │ 画像：行尾注释枚举 a|b|c、  │
│   休眠配置:、!! 哨兵        │  │   !!!/!!!! 警告             │
└─────────────────────────────┘  └─────────────────────────────┘
               ▼                                ▼
        param.py 金样本                config.yaml 金样本
       （模块常量配置）                （ROS 2 参数文件）

  v2 计划：TOML 适配器（tomlkit）、INI 适配器（configupdater）
```

层间职责边界（**必须**遵守）：

1. **前端层**只消费 §3 的数据结构（ConfigDoc/ConfigItem/Diagnostic），渲染 UI、收集 EditOp。前端**不得**感知具体格式细节（不得出现"这是 YAML"的分支逻辑）；"推测"徽标、灰显、黄标等展示规则由语义模型字段驱动（§3.5）。
2. **核心语义模型**负责：数据结构定义、条目/文档级不变量校验（§3.9）、编辑生命周期与提交门控（§7.5）、外部修改检测与基线校验（§7.6）、原子写（§7.4）。核心**不得**解析任何具体格式。
3. **适配器层**负责：格式嗅探、解析为 ConfigDoc、按 EditOp 做 token 级替换并序列化为字节。适配器**不得**做 I/O 落盘（写盘由核心统一原子写），**不得**修改与其无关的语义（如 Python 适配器不产生 YAML 风格枚举）。

稳定接口是 §3 的数据结构 + §4.1 的 Adapter 接口 + §9 的 CLI 契约。三者变更都必须升版本号。

## 3. 语义模型规范

### 3.1 ConfigItem

ConfigItem 是语义模型的基本单元，对应"一个可配置的标量"。字段定义（实现可增补，不得删减语义）：

| 字段 | 类型 | 规范 |
|---|---|---|
| `path` | str | **唯一路径**。yaml：点分嵌套路径，如 `rl_brain.ball_vel.alpha`（包装链剥离规则见 §4.4 Y-4）；python：模块级变量名，如 `KICK_POWER_MIN` |
| `group` | str | 所属分组名。yaml：分组键（如 `strategy`）；python：`# ====` 节标题（如 `踢球力度`）。条目散落在分组层时归入伪分组 `（根级）`（yaml）或 `（未分组）`（python） |
| `subgroup` | str \| None | 子分组。python：`# --- 标题 ---`（如 `READY 阶段站位（_act_ready 用）`）；yaml v1 恒为 None |
| `type` | `'bool'\|'int'\|'float'\|'str'\|None` | v1 仅此四种标量类型；None 表示只读且类型未知（如 tuple 表）。判定规则见 §8.1 |
| `value` | bool\|int\|float\|str \| None | 当前值。**必须**与 `raw_literal` 解析结果一致 |
| `raw_literal` | str | 原始字面量 token 的**逐字符文本**，如 `100.`、`"adult_size"`、`True`、`-6.5`、`0.90` |
| `literal_style` | LiteralStyle | 字面量风格的结构化记录（§3.2），落盘时按 §7.2 重放 |
| `description` | `list[Section]`，`Section = {label: str\|None, text: str}` | 说明段。python：作用/影响/建议 分段 + 前导段；yaml：单段自由文本（label=None）。`description_provenance: 'comment'\|'declared'` |
| `enum_candidates` | `list[{value, label: str\|None, provenance}]` | 候选枚举，可为空。provenance ∈ {declared, inferred} |
| `range` | `None \| {min, max, unit: str\|None, provenance}` | 范围约束，0 或 1 个。min/max 均可为空（**单边界约束合法**，空侧不设限；`@min`/`@max` 为独立可选键，§6），unit 仅展示（如 `米`、`秒`、`米/秒`）。provenance ∈ {declared, inferred} |
| `readonly` | bool | 只读标志 |
| `readonly_reason` | str \| None | 只读原因，取值见 §3.5 |
| `dormant` | bool | 休眠标记（§3.5） |
| `warning` | bool | 警告标记（§3.5） |
| `warning_reason_text` / `dormant_reason_text` | str \| None | 标记注释原文（§3.5），UI 展示依据 |
| `locator` | opaque | **写回定位信息，适配器私有**（行号、CST 节点引用等）。核心与 UI **不得**解释、复制或持久化 locator；跨进程边界时允许将其置空（此时该 doc 不可再提交，必须重新 load） |

约束（范围/枚举）与类型各自携带 provenance；说明段单独携带 `description_provenance`。UI **必须**对所有 `inferred` 的约束显示"推测"徽标（§5.1）。

### 3.2 字面量与字面量风格（LiteralStyle）

`raw_literal` 是保真写回的锚点：**落盘时未被用户改动的值必须按原字面量原样写回**（由 §7.3 T1 保证）；被改动的值按原风格重放（§7.2）。

v1 统一的 LiteralStyle 字段（适配器可私有扩展）：

| 字段 | 取值 | 适用 | 金样本示例 |
|---|---|---|---|
| `float_form` | `'plain'` \| `'trailing_dot'` \| `'fixed(p)'`（p=固定小数位数） | float | `plain`：`0.15`；`trailing_dot`：`100.`；`fixed(2)`：`1.60`、`0.90`；`fixed(1)`：`1.0`、`10000.0` |
| `bool_case` | `'lower'` \| `'capital'` | bool（yaml） | `true`（config.yaml L184）与 `True`（config.yaml L150） |
| `quote` | `'none'` \| `'single'` \| `'double'` | str（python / yaml） | `double`：`"adult_size"`；`none`：裸标量 |
| int 形式 | v1 仅 `'decimal'` | int | `10000`、`2300`、`3` |

`float_form` 判定规则（对既有字面量可机械执行，保证 M1 测试可复现）：字面量以 `.` 结尾 → `trailing_dot`；小数部分末位为 `0` → `fixed(p)`（p = 小数位数，如 `0.90`→2、`1.0`→1）；其余 → `plain`。

数值字面量含下划线（`1_000`）、指数（`1e3`）、十六进制（`0x10`）之一者，v1 **必须**按只读处理（金样本中不存在，此规则保证风格重放的确定性）。

一切**带前缀的字符串字面量**（`r''` / `b''` / `f''` 及前缀组合）视为非纯 str 字面量，v1 **必须**按只读处理（§4.3 R-3），不参与风格重放。str 新值的转义写回规则见 §7.2（按原 quote 风格标准转义重放）。

### 3.3 说明段（Description）

- python：条目上方连续 `#` 块按 §5.2 的 P-2 规则切分为有序 Section。示例（param.py L25–30）：

  ```
  # 作用: kick() 力度下限夹取(无量纲),低于该值的力度被抬高到该值。
  # 影响: 所有踢球的最小力度(player.py kick() 内 power_clamped)。
  # 建议: [1.0, 2.0]。SDK SoccerKickManager.update_command 合法力度范围 1.0–10.0,
  #   越界抛 ValueError;原值 0.1 低于 SDK 下限;现役调用均 ≥1.85,
  #   故取 1.0 对齐 SDK 下限,此修正不改变当前行为。
  KICK_POWER_MIN = 1.0
  ```

  得到 3 个 Section：`作用` / `影响` / `建议`，缩进续行（`#   越界抛…`）并入上一段。
- yaml：行尾注释即说明全文。示例（config.yaml L145）：`alpha: 0.5 # 低通系数: lp = alpha·v_raw + (1-alpha)·lp` → 单 Section（label=None）。
- 说明**只展示、不校验**；"建议:"里的"保持 x.x"等评价文字不解析为约束（§5.2 P-10）。

### 3.4 约束与 provenance

- `range`：来自 `建议: [a, b]` 模式（inferred，§5.2 P-6）或 `@min/@max`（declared，§6）。
- `enum_candidates`：来自行尾注释 `a | b | c`（inferred，§5.3）或 `@enum`（declared，§6）。
- **优先级**：同一约束字段上 `declared` 覆盖 `inferred`；declared 与 inferred **不得**同时并存于一个条目的同一字段。
- `provenance` 决定校验级别（§8.2）：declared 违规→拦截不落盘；inferred 违规→黄色警告、照常提交落盘。

### 3.5 状态标志：readonly / dormant / warning

| 标志 | 含义 | 来源（金样本实例） |
|---|---|---|
| `readonly=true` | 条目在 GUI 中可见但不可编辑 | `readonly_reason` 枚举：`'non_literal'`（值是表达式，如 `PLAN_STEP = math.radians(15)`，param.py L784）；`'container'`（值为元组/序列/表，如 `KICK_POWER_BY_X`、`READY_OUR_KICKOFF_SLOT1_XY = (-0.15, 1.4)`）；`'anchor'`（yaml 锚点子树）；适配器可扩展，扩展值必须在适配器文档中登记 |
| `dormant=true` | 休眠条目：作者声明当前不生效 | python 注释行以 `休眠配置:` 开头（param.py L427，如 `CENTRE_KICKOFF_ANGLE_START_DEG`）；yaml v1 无此标记 |
| `warning=true` | 警告条目：作者标注了危险/哨兵语义 | 注释中出现 ≥2 个连续 `!`（通用规则，§5.1）：python `# !! 哨兵值,非场地坐标 !!`（`X_STRAIGHT_M`，param.py L664–668）、`# !! 哨兵伪方向向量分量,不是场地坐标 !!`（`X_OUR_KICKOFF_TARGET` / `Y_OUR_KICKOFF_TARGET`）；yaml `treat_person_as_robot` 的 `!!!! 正式比赛时, 必须设置为 false !!!!`（config.yaml L9） |

UI 展示要求（v0.4 修订）：readonly 灰显禁改；dormant **允许编辑并实时落盘**，控件持续黄标并提示“当前不生效（休眠配置）”（§10 U-8）；warning 黄标。悬停/详情面板**必须**展示标记的原文依据（`warning_reason_text` / `dormant_reason_text` 存标记注释原文）。

### 3.6 ConfigDoc

| 字段 | 类型 | 规范 |
|---|---|---|
| `format` | str | 适配器注册名（`'python'` / `'yaml'`） |
| `path` | Path | 源文件绝对路径 |
| `description` | str \| None | 文档级描述。python：模块 docstring（param.py L1–12 的"集中调参入口。……注释约定:……"）；yaml：None |
| `items` | list[ConfigItem] | 按文件出现顺序排列 |
| `groups` | list[{name, description: str\|None}] | 分组结构，按出现顺序。yaml：顶层包装链剥离后的第一层键（§4.4 Y-4），组描述来自组键上方的独立注释块（如 config.yaml L116–121 → `rl_brain` 组描述）；python：`# ====` 节（组描述来自节内"本节总览:"段，param.py L22–23） |
| `diagnostics` | list[Diagnostic] | 加载期诊断（§3.7） |
| `original_bytes` | bytes | 会话基线字节：load 时为原始文件字节，每次成功提交后更新为已落盘字节（§7.5、§7.6） |
| `content_hash` | str | `original_bytes` 的 sha256（§7.6 提交前基线校验） |

分组语义明确化：

- **yaml**：分组 = 包装链剥离后第一层映射的键。config.yaml 金样本分组为 `game / ball_predictor / robot / strategy / obstacle_avoidance / locator / rl_brain / rerunLog / recovery / vision / debug / sound` 共 12 组；直接散落在该层的标量叶子（`enable_com`、`game_control_ip`）归入伪分组 `（根级）`。
- **python**：分组 = `# ====` 节标题。param.py 金样本共 13 组（踢球力度、Player 走位控制、Player 踢球 / 射门规划、Player 技术动作参数：守门 / 支援、Normal 阶段策略、防守 / 回防(chaser 轨迹选人 + support 封堵 + guard 出击)、开球 / 定位球策略、站位 / 避让、踢球目标几何、障碍物几何参数、全局路径规划器 (A* Grid Planner)、局部路径规划器 (VFH Direction Scan)、可视化）；节内 `# --- 标题 ---` 形成 subgroup（共 7 个，如 `# --- READY 阶段站位（_act_ready 用） ---`、`# --- 中场开球扫描(Centre Kickoff) ---`）。

（上述计数为规范 v0.1 撰写时点对金样本的核对值，作为 M2 验收基准，见 §11。）

### 3.7 Diagnostic

```text
Diagnostic {
  severity: 'error' | 'warning' | 'info'
  code:     str          # 见下表
  message:  str          # 面向用户的中文说明，须包含可定位信息
  path:     str | None   # 关联条目路径
}
```

v1 诊断码表：

| code | severity | 含义 |
|---|---|---|
| `E-FORMAT` | error | 无法识别文件格式（所有适配器 detect 均失败） |
| `E-PARSE` | error | 格式识别成功但解析失败（含 yaml 多文档 `E-PARSE-MULTIDOC`） |
| `E-ENCODING` | error | 非 UTF-8 编码 |
| `E-DUP-KEY` | error | yaml 重复键 |
| `E-DUP-ASSIGN` | error | python 同名重复赋值 |
| `W-INFER-CONFLICT` | warning | 条目当前值违反 inferred 约束（加载期发现，如 §5.2 的反例） |
| `W-EOL-MIXED` | warning | 文件行尾风格混杂，逐行保真为尽力而为 |
| `I-ENUM-DROPPED` | info | 注释中某 `\|` 分段无法解析为候选，已丢弃（§5.3） |
| `I-SEQ-READONLY` | info | yaml 序列值按只读处理（v1） |
| `I-ANCHOR-READONLY` | info | yaml 锚点子树按只读处理（v1） |

不变量：诊断的 `path` 非空时必须指向已存在的条目。severity 为 warning 的加载期诊断**不阻塞**文件进入编辑（呈现方式见 §10 U-10，v0.4 决议）。

### 3.8 EditOp

```text
EditOp { path: str, new_value: bool | int | float | str }
```

- 一次提交 = `list[EditOp]`（实时落盘模型下通常为单条）。UI 撤销 = 对该条目施加反向 EditOp 并立即提交落盘（§7.7）。
- EditOp 只带新**值**，不带字面量文本；字面量文本由适配器按 `literal_style` 生成（§7.2）。
- 引用不存在的 `path` 属于程序错误，核心必须拒绝（抛错，不产生 Diagnostic）。

### 3.9 语义模型不变量（必须可测试）

- **I-1 路径唯一**：同一 ConfigDoc 内 `path` 不得重复。
- **I-2 值与字面量一致**：`value` 必须等于按格式解析 `raw_literal` 的结果。
- **I-3 恒等往返**：对金样本，`load → save(空 edits)` 输出字节与原文件**完全一致**（§7.3 T1）。
- **I-4 外科手术边界**：`save(edits)` 的输出与 `original_bytes` 的行级 diff 中，变更行数等于 edits 触及的行数（v1 每条 edit 恰好 1 行），且每条 edit 的目标行包含其新字面量 token（§7.3 T2）。
- **I-5 未触碰条目字节不变**：未出现在 edits 中的条目，其 `raw_literal` 在输出中逐字符出现。
- **I-6 推测永拦截**：`provenance='inferred'` 的约束违反**不得**导致提交被阻止，只产生持续黄色警告（§7.5）。
- **I-7 徽标一致**：所有 `provenance='inferred'` 的约束在 UI 上有"推测"标识。

### 3.10 会话与多文档

- 每个已打开文件对应**一个 ConfigDoc**；多文件会话（§10 U-2）是 UI 会话层对多个 doc 的管理（"活动文件"概念属 UI 层，不属于语义模型），核心不引入新数据结构。
- **写回按文件独立**：各 doc 拥有独立的未提交暂态、防抖计时、undo/redo 栈、基线（`original_bytes` / `content_hash`）与提交流程；一个文件的提交失败或基线冲突**不得**阻塞其他文件的提交（§7.5、§7.6）。
- 稳定接口（§2）不变：跨进程边界时仍按单 doc 传输，会话层由前端组合。

## 4. 适配器接口规范

### 4.1 接口伪代码

```python
class Adapter(Protocol):
    name: str                    # 注册名："python" | "yaml"
    extensions: tuple[str, ...]  # (".py",) / (".yaml", ".yml")

    def detect(self, path: Path, head: bytes) -> bool:
        """是否由本适配器处理。扩展名优先，内容嗅探兜底。不得抛异常。"""

    def load(self, path: Path) -> tuple[ConfigDoc, list[Diagnostic]]:
        """解析文件。任何可读输入都不得抛异常：
        失败一律以 error 级 Diagnostic 表达（如 E-PARSE / E-ENCODING）。
        ConfigDoc.original_bytes / content_hash 由适配器负责填充。"""

    def save(self, doc: ConfigDoc, edits: Sequence[EditOp]) -> bytes:
        """对 doc（必须是本适配器 load() 的产物，locator 有效）逐条应用
        EditOp：token 级替换 + 字面量风格重放，返回新文件完整字节。
        不落盘（写盘由核心的原子写负责，§7.4）。
        edits 引用未知 path → 抛异常（程序错误）。"""
```

编码契约：核心在调用适配器前统一处理字节层——检测编码（v1 仅 UTF-8，否则 `E-ENCODING`）；若存在 UTF-8 BOM 则剥离并记录，写回时由核心补回 BOM；适配器见到的永远是 BOM-less 文本。换行符（LF/CRLF）由适配器原样保留（混杂风格时逐行保留，尽力而为，并给 `W-EOL-MIXED`；混杂 = 同一文件内 LF 与 CRLF 并存，单一风格不告警）。

### 4.2 注册表与格式嗅探

- 注册表为**有序列表** `[PythonAdapter, YamlAdapter]`（v1 固定顺序即可；新适配器追加）。
- `--format` 显式指定时直接选定（§9.1），选定适配器 load 失败 → exit 2，**不得**回退其他适配器。
- `auto`：先按扩展名匹配 `extensions`；命中唯一则用该适配器，再用内容嗅探确认（确认失败 → `E-PARSE`，不换适配器）；扩展名未命中则按注册表顺序逐个 `detect` 内容嗅探（yaml：可被 ruamel 解析为单文档 mapping；python：可被 libcst 解析为模块）。全部失败 → `E-FORMAT`，exit 2。
- 空文件（v0.4 决议）：0 字节 `.py` → python 适配器正常加载为 **0 条目**，正常打开为空会话；0 字节 `.yaml` → 解析结果非 mapping，按 `E-PARSE` 出诊断（Y-1），确认失败不换适配器。
- 新适配器接入 = 实现三方法 + 注册 + 提供注释画像（§5）+ 金样本往返测试；核心代码零改动。

### 4.3 Python 适配器（v1）

实现库：**libcst**（保留格式的 CST）。适用范围：模块顶层（缩进级别 0）的赋值语句。可编辑性判定规则（按序执行）：

- **R-1** 仅考虑模块顶层语句；`import` / `def` / `class` / `if` / docstring 等不产生条目（param.py 的 `_lookup_kick_power_table`、`kick_power_for_x`、`kick_power_for_x_and_angle` 三个函数与 import 不出现在条目列表）。
- **R-2** 仅 `Assign` / `AnnAssign`、单目标、目标为 `Name`。`AnnAssign` 的类型注解仅作展示信息；注解与 RHS 字面量类型冲突 → `warning` 诊断（不改变 type 判定，§8.1）。
- **R-3** RHS 为标量字面量（`True`/`False`、十进制 int、十进制 float（含一元负号）、str 字面量）→ **可编辑条目**。例：`KICK_POWER_MIN = 1.0`（float）、`X_OUR_KICKOFF_TARGET = 10000`（int）、`GUARD_FACE_BALL = True`（bool）、`GUARD_HOME_X = -6.5`（负 float）。带前缀的字符串字面量（`r''` / `b''` / `f''` 等）不视为纯 str 字面量 → 走 R-4（带条目注释块 → 只读条目，`readonly_reason='non_literal'`；否则不生成条目；v0.4 决议）。
- **R-4** RHS 为其他表达式（如 `PLAN_STEP = math.radians(15)`、`PLAN_MAX_OFFSET = math.radians(100)`）→ 若该赋值带 §5.2 定义的条目注释块（含 作用/影响/建议），生成**只读条目**（`readonly_reason='non_literal'`）；否则不生成条目。
- **R-5** RHS 为元组/列表/字典/集合字面量（如 `KICK_POWER_BY_X` 力度表、`READY_OUR_KICKOFF_SLOT1_XY = (-0.15, 1.4)`）→ 生成**只读条目**（`readonly_reason='container'`，type=None，value=None，raw_literal 保留全文）；对其 §5.2 推测（范围/枚举）不执行（v1）。
- **R-6** 同名重复赋值 → `E-DUP-ASSIGN` error 诊断，以首个为准。
- **R-7** v1 只编辑"模块顶层简单赋值的标量字面量"，其余一律只读不显示或按 R-4/R-5 只读显示——**不得**扩大可编辑范围。

已知风险表（Python 格式）：

| 风险 | 金样本证据 | 缓解 |
|---|---|---|
| 赋值号对齐空格被归一化 | `CENTRE_KICKOFF_ANGLE_END_DEG   = -70.0`（三空格，param.py L437） | 只替换 RHS 值 token，等号两侧空白不动（libcst 逐 token 替换天然满足；T4 测试覆盖） |
| 注释与条目的归属判错 | 注释块与赋值间不得有空行；`# 开球`（L341）这类短注释属于下一条目前导段 | P-1 明确"紧邻、连续、无空行"；归属规则有单测 |
| 元组内空格差异 | `READY_OUR_KICKOFF_SLOT3_XY = (-4.0,-1.5)` 无空格 vs `(-0.15, 1.4)` 有空格 | v1 元组只读、原样保留，无重排风险；v2 编辑时必须逐字符保留内部空白 |
| 文件本质是代码的误编辑 | param.py 含函数与跨常量语义（哨兵成对） | R-7 范围收窄 + 不执行代码 + 哨兵类条目 warning 黄标（§3.5）；跨字段校验明确非目标（§1.2） |
| 无 str 常量 | 金样本 param.py 无 str 标量 | 验收中 str 编辑由 config.yaml 覆盖（§11 A-4） |

### 4.4 YAML 适配器（v1）

实现库：**ruamel.yaml** round-trip 模式（保留注释、空行、锚点、引号风格）。规则：

- **Y-1** 仅支持单文档 mapping 结构；多文档（`---` 分隔）→ `E-PARSE-MULTIDOC`；顶层非 mapping → `E-PARSE`。
- **Y-2** 条目 = 叶子标量。类型按 YAML 1.2 core 语义解析；**带引号的标量一律为 str**（如 `server_ip: "192.168.10.110:9876"` 是 str 而非"看起来像 IP 的东西"）。
- **Y-3** 嵌套 mapping 递归展开为条目，路径点分连接，如 `rl_brain.ball_vel.alpha`；`strategy.shoot.xmin` 等深层叶子必须出现在条目列表。
- **Y-4 包装链剥离**：从根开始，只要当前 mapping 恰有一个键且值为 mapping，则该键为包装键（wrapper），记入包装链并下钻。config.yaml 金样本包装链为 `brain_node → ros__parameters`；`path` 从包装链之下起算（故为 `rl_brain.ball_vel.alpha` 而非 `brain_node.ros__parameters.rl_brain.ball_vel.alpha`）。分组 = 剥离后第一层映射的键（§3.6）。
- **Y-5 注释掉的行不是条目**：`# image_topic: "/image_left_raw" # d-robotics`、`# cam_pixel_width: 544. # 相机像素宽度, d-robotics`（config.yaml L166–169、L174–175）不产生条目，由 ruamel 作为注释原样保留。同名键的注释副本与活动条目并存时（`cam_pixel_width`），条目只有一个（活动行）。
- **Y-6** 序列值 → 只读条目（`readonly_reason='container'`，展示原始字面量），`I-SEQ-READONLY`；锚点/别名子树 → 只读（`'anchor'`），`I-ANCHOR-READONLY`（金样本无锚点，规则为前瞻）。
- **Y-7** 重复键 → `E-DUP-KEY` error 诊断，条目取首现，文件原样保留（不改写重复键）。
- **Y-8** 布尔按原文解析：`True` 与 `true` 都是 bool（值相同），但 `literal_style.bool_case` 不同，写回时各回各家（§7.2）。
- **Y-9**（v0.4）块标量（`|`、`>`）与 `.nan` / `.inf` 等非普通标量的叶子 → **只读条目**（`readonly_reason='non_plain_scalar'`，本适配器登记的扩展值，§3.5），说明面板标注原因；v1 不提供编辑。

## 5. 注释画像（comment profile）规范

### 5.1 通用要求

- **C-1 推测必标注**：凡由启发式得到的约束/候选，`provenance='inferred'`，UI **必须**带"推测"字样徽标（I-7）。用户界面上不得把推测约束呈现为事实。
- **C-2 推测不拦截**：inferred 约束违规只产生黄色警告，**不得**阻止提交落盘，条目持续黄标（I-6）。
- **C-3 警告标记通用规则**：任何适配器的注释中出现 ≥2 个连续 `!`（前后不是字母或数字）→ 条目 `warning=true`，并记录该行原文为展示依据。
- **C-4 画像即契约**：每个适配器**必须**在本文档（或其附录）维护画像规则；画像规则变更**必须**同步更新金样本测试。

### 5.2 Python 画像

规则编号 P-n，全部针对 §4.3 R-3 定义的可编辑标量条目（readonly 条目不做推测，见 R-5）：

- **P-1 条目注释块**：紧邻赋值行上方、连续的 `#` 行（中间不得有空行）。块内每行去掉行首 `#` 与一个可选空格后进入解析。
- **P-2 分段**：行首为 `作用:` / `影响:` / `建议:`（全角冒号 `：` 同样接受）时开启对应新段；以 ≥2 空格缩进开头的行并入上一段；其余无标签行作为前导段（label=None）。param.py L25–30 为正例（§3.3）。
- **P-3 文档描述**：模块 docstring → `ConfigDoc.description`（param.py L1–12）。
- **P-4 分组头**：`#` + ≥10 个 `=` 的行开启组头序列；其后的第一行非空 `#` 行为组名；再一个 `====` 行结束组头。组头后紧邻的"本节总览:"段为组描述（param.py L19–23）。首个组头之前若出现可编辑条目，归入伪分组 `（未分组）`。
- **P-5 子组头**：以 `# ---` 开头的注释行在当前组内开启新 subgroup，标题取该行剩余文本（结尾的 `---` 可省略，如 param.py L518）；子组头行由结构解析先消化，**不并入**相邻条目的注释块（即使与条目注释块紧邻，如 param.py L533–536）。param.py 金样本共 7 处：L244、L366（`# --- READY 阶段站位（_act_ready 用） ---`）、L416（`# --- 中场开球扫描(Centre Kickoff) ---`）、L478、L518、L533、L539。
- **P-6 范围推测**：在"建议"段中搜索模式 `\[ <num> , <num> \]`（`num = -?\d+(\.\d+)?`，允许空白）。排除以下两种非范围情形：(a) `[` 前紧邻（忽略空白）是 `+ - * × /` 之一（增量表达式，如 `建议: KICK_ENTER_M + [0.2, 0.6] 米`，param.py L188）；(b) 前缀 `±`（对称带，如 `建议: ±[1, 5] 度`，param.py L442；v1 不解析对称带）。命中则 `range={min, max, provenance:'inferred'}`；`]` 之后到下一个句读符（。；;,、）之间的单位文本作为 `unit` 展示（如 `米`、`米/秒`、`米/格`、`1/秒`）。
- **P-7 休眠标记**：注释块中任一行以 `休眠配置:` 开头 → 条目 `dormant=true`，该行原文作为展示依据。正例（param.py L427–431）：

  ```
  # 休眠配置: 仅被 _select_centre_kickoff_target 引用,其唯一调用点是 main.py 中刻意保留的注释代码块(中场开球动态扫描,便于回滚),当前固定目标版本不生效。
  # 作用: 扫描起始角(度)。
  ...
  CENTRE_KICKOFF_ANGLE_START_DEG = -25.0
  ```

- **P-8 警告标记**：按通用规则 C-3。正例：`# !! 哨兵值,非场地坐标 !!`（`X_STRAIGHT_M`）。
- **P-9 推测范围**：仅对可编辑条目执行；readonly 条目（tuple 表等）上出现 `[a, b]` 文案（如 KICK_POWER_BY_X 的"每行 power∈[1.0, 10.0]"）不产生约束。
- **P-10 "保持 x"不解析**：`建议` 段中"保持 1.2""保持 True"等评价文字仅展示，**不得**解析为约束或默认值。（负向测试：`KICK_ENTER_M = 1.4` 的注释写"保持 1.2"（param.py L183–184），**不得**产生任何冲突警告。）

**已知冲突正例（必须作为 W-INFER-CONFLICT 测试）**：param.py L552–555

```
# 作用: x_advance 扫描下限(米),即最短推进量。
# 影响: 边线球推进量扫描下界。
# 建议: [1.5, 3.0] 米。保持 2.0。
THROW_IN_ADVANCE_MIN_M = -2.0
```

当前值 -2.0 不在推测范围 [1.5, 3.0] 内 → 加载期产生 `W-INFER-CONFLICT` 黄色警告；因是推测，**不阻塞提交**（编辑照常落盘并持续黄标）。`CORNER_KICK_POWER = 1.6` vs `建议: [3.0, 8.0]`（L527–531）同理。

### 5.3 YAML 画像

规则编号 YC-n：

- **YC-1 行尾说明**：叶子所在行 `#` 后的文本（trim）即该条目说明（单 Section，label=None）。正例：`alpha: 0.5 # 低通系数: lp = alpha·v_raw + (1-alpha)·lp`。
- **YC-2 组描述**：分组键上方的独立注释块（连续 `#` 行）→ 该组 `description`。正例：config.yaml L116–121 的 RL Brain 说明块挂在 `rl_brain:` 上；L182 `# for fun` 挂在 `sound:` 上。
- **YC-3 枚举推测**：说明中含 ≥2 个由 `|` 分隔的段时触发，逐段解析候选：
  1. 按 `|` 切分；
  2. 段清洗（按序执行）：(i) 段中含 `——` 则截去其后备注（正例 `backend` 末段 `stub(安全停车) —— 旧 libtorch/.pt 契约过期…` → `stub(安全停车)`）；(ii) 若存在紧邻左侧无空白的 `=`（形如 `token=…`）→ 该 token 为候选、`=` 右侧文本为展示 label（正例 `mirror` 注释的 `off=关 (默认, …)` → `off`；`goalie_mode` 首段 `点球守门员模式: rl=守门员也走 RLDecide` → `rl`）；(iii) 否则剥离尾部成对 `(...)` 括注（正例 `policy_np(C++ 移植, 零新依赖, 默认)` → `policy_np`、`stub(安全停车)` → `stub`）；(iv) 若仍含 `:` 或 `：` 取最后一个冒号之后的部分（正例 `backend` 首段剥离括注后为 `推理后端: policy_np` → `policy_np`）；(v) trim；
  3. 按 YAML 1.2 core 语义解析候选；失败 → 丢弃并给 `I-ENUM-DROPPED`；
  4. 候选含空白字符或 CJK 字符 → 丢弃并给 `I-ENUM-DROPPED`（防误判闸门）；
  5. 候选类型与条目 `type` 不一致 → 丢弃并给 `I-ENUM-DROPPED`；
  6. 剩余 ≥2 个候选 → `enum_candidates`（`provenance:'inferred'`）；否则不产生枚举。
- **YC-4 触发正例**（config.yaml，全部必须出现在 M2 验收的推测枚举中）：

  ```
  player_id: 3 # 1 | 2 | 3 | 4 | 5
  field_type: "adult_size" # adult_size | kid_size | robo_league
  player_role: "striker" # striker | goal_keeper
  player_start_pos: "right" # right | left
  backend: "policy_np" # 推理后端: policy_np(...) | libtorch | onnx | stub(安全停车) —— …
  goalie_mode: "rl" # 点球守门员模式: rl=… | classic=…
  mirror: "off" # team1 镜像: off=关 (…) | auto=旧自动逻辑 | true=强制镜像 (…)
  ```

- **YC-5 丢弃负例**（必须作为 I-ENUM-DROPPED 测试）：`own_color: "" # 我方队服颜色 red|blue|空=未知, …` 中候选 `空` 因含 CJK 被丢弃（真实语义是"空字符串"，启发式无法可靠还原，宁缺勿错）；`mirror` 注释的 `true` 因类型为 bool 与 str 条目不符被丢弃。`opponent_theta_mode` 注释无 `|` → 不触发枚举推测。
- **YC-6 推测枚举仅建议**：下拉框列出候选（带"推测"徽标与 label），但**必须**允许用户输入列表外的合法值；提交时若值不在候选内 → 黄色警告（非拦截，照常落盘并持续黄标）。declared `@enum`（§6）才限制为列表内取值。
- **YC-7 休眠**：yaml v1 无休眠标记约定。

## 6. 可选结构化标注（v1.5 增强，非前置条件）

对老文件的零迁移成本是硬要求，因此注释启发式（§5）是 v1 的唯一约束来源。结构化标注是 **v1.5 的可选增强**：仅新项目自愿采用，带标注的条目获得确定性约束。

语法：在条目注释块（python）或行尾注释（yaml）中书写 `@key=value` 序列：

```
# @type=int @min=1 @max=10 @default=3 @enum=a|b @desc=采样数 @unit=帧
SAMPLE_COUNT = 3
```

- 键集 v1.5：`type` / `min` / `max` / `default` / `enum`（`|` 分隔）/ `desc` / `unit` / `readonly`。未登记的 `@key` → `info` 诊断并忽略。
- `@min` 与 `@max` 为**独立可选键**，可只写其一（单边界约束；range 的 min/max 均可空，§3.1、§8.2；v0.4 决议）。
- **优先级**：@ 标注（`provenance='declared'`）覆盖注释推测；同一字段 declared 与 inferred 不得并存（§3.4）。
- **校验级别**：declared 的 type/enum/range 违规 → 拦截（§8.2）；`@default` 供 UI"恢复默认"。
- 合法性：`@type` 取值限 §3.1 四种标量；`@enum` 候选须能解析为 `@type` 类型，否则 `error` 诊断。
- 无标注条目行为与 v1 完全一致。

## 7. 写回与保真规则

### 7.1 外科手术式替换

落盘**必须**满足：只对目标条目的字面量 token 做替换；该行其余部分（键名、赋值号/冒号、等号两侧空格与对齐、行尾注释、尾随空格）与其他所有行完全不动。实现路径：适配器基于 CST 定位 token 替换（libcst）或 round-trip 原位改值（ruamel），**不得**"重新序列化整个文档"。

### 7.2 字面量风格重放规则

被编辑的值按原条目 `literal_style` 生成新字面量。规则表（全部为 T3 测试用例，示例取自金样本真实字面量）：

| 场景 | 原字面量 | 用户新值 | 必须写回 | 规则 |
|---|---|---|---|---|
| yaml 尾点浮点 | `100.`（step_interval） | `1920` | `1920.` | trailing_dot 且新值为整数 → `N.` |
| yaml 尾点浮点 | `100.` | `0.5` | `0.5` | 新值非整数 → 最短表示 |
| yaml 尾零浮点 | `0.90`（robot_height） | `1.05` | `1.05` | fixed(2) → 恰好 2 位小数 |
| yaml 尾零浮点 | `0.90` | `1.2` | `1.20` | fixed(2) 不足位补零 |
| python 尾零浮点 | `1.60`（SETPIECE_DISTANCE_FROM_BALL） | `2` | `2.00` | fixed(2) 补零 |
| python `.0` 浮点 | `10000.0`（X_STRAIGHT_M） | `20000` | `20000.0` | fixed(1) |
| 布尔大小写 | `True`（enable_com, yaml） | false | `False` | bool_case='capital' |
| 布尔大小写 | `true`（enable, yaml） | false | `false` | bool_case='lower' |
| 引号风格 | `"adult_size"` | kid_size | `"kid_size"` | quote='double' |
| 裸字符串 | （无金样本实例） | — | 裸写；若新值裸写不合法（含 `: `、前导特殊字符等）→ 回退双引号 | quote='none' 安全回退 |
| str 转义重放 | `"say \"hi\""`（无金样本实例；原值含转义引号） | `he said "hi"` | `"he said \"hi\""` | quote='double'，新值内引号等特殊字符按该风格标准转义 |
| int | `10000`（X_OUR_KICKOFF_TARGET） | `20000` | `20000` | 十进制原样 |
| 负数 | `-6.5`（GUARD_HOME_X） | `-7` | `-7.0` | float + fixed(1) |

**禁止（反例）**：把 `100.` 写成 `100.0`；把 yaml 的 `True` 写成 `true`（或反之）；把 `1.60` 写成 `1.6`；把 `"espeak"` 写成 `espeak`；把含引号 / 反斜杠 / 换行的 str 新值不加转义直接写入；改动等号/冒号两侧空格与对齐（如 `CENTRE_KICKOFF_ANGLE_END_DEG   = -70.0` 的三个空格，param.py L437）。

浮点格式化的数值语义：风格重放只改变字符串表示，**不得**改变数值（`2.00` 与 `2.0` 数值相等，允许；`2` 写入 float 条目必须落成 `2.0` 系风格，不得写成 int 字面量）。

**str 转义写回（v0.4）**：新值按原字面量 quote 风格重放（单 / 双引号保留）；新值中的引号、反斜杠、换行等特殊字符，按该 quote 风格在目标格式中的标准转义规则写入（如双引号风格中 `"` → `\"`）。一切带前缀的字符串字面量（`r''` / `b''` / `f''` 等）为只读，不进入本规则（§3.2、§4.3 R-3）。

### 7.3 字节级不变保证与金样本测试

写回保真由以下测试矩阵看门（M1 起进入 CI，输入为 `testdata/` 中的金样本拷贝）：

- **T1 恒等往返**：`load → save(空 edits)` 输出字节 == 原始字节。两金样本各一例。
- **T2 单点手术**：对任取条目应用单条 EditOp，输出与原文件的 unified diff **恰好 1 个变更行**，且该行含新字面量。
- **T3 风格回归**：§7.2 规则表逐行断言，含 str 转义断言用例（原值含转义引号等特殊字符时的新值写回，如 `"say \"hi\""` → `"he said \"hi\""`；v0.4）。
- **T4 逐字节行比对**：T2 输出中除变更行外每行与原文件逐字节一致（含行尾空格；config.yaml 多数行有尾随空格，是专门考察点）。

### 7.4 原子写与文件属性

每次落盘**必须**按以下顺序（可测试）：

1. 在目标文件**同目录**创建临时文件（如 `.config.yaml.configer-tmp`）；
2. 写入适配器返回的完整字节，`fsync`；
3. 将临时文件权限 `chmod` 为原文件模式（stat 逐位复制）；
4. `rename` 原子替换目标文件（同目录保证同文件系统）；
5. fsync 所在目录（尽力而为）。

除本次提交写入外，configer **不得**以任何方式改动目标文件。非 UTF-8 编码在 load 期拒绝（`E-ENCODING`），因此不存在写坏编码的问题；BOM 由核心剥离/补回（§4.1）。

### 7.5 编辑生命周期与提交门控

v0.3 起**不存在"保存"动作**：编辑实时落盘，盘上永远保持最后一个合法状态。生命周期（每文件独立执行，§3.10）：

1. **输入 → 暂态**：用户输入先进入内存暂态，控件立即反映输入值；
2. **门控校验**（§8.2，只针对被编辑条目）：类型错误或 declared range/enum 违规 → 暂态**不进入提交**，控件红标并展示原因（declared 展示 @ 标注原文）；inferred 违规 → 仅黄色警告，暂态照常进入提交，条目持续黄标（"推测不作铁律"，I-6）；
3. **提交时机（按控件分型，v0.4 决议）**：bool / 枚举下拉等**点击类控件**值变化即提交（无防抖）；int / float / str 等**文本输入控件**在最后键击后 **400ms** 防抖提交；控件失焦时立即提交，不等防抖（切换活动文件、关闭文件均视为失焦）；
4. **提交（commit）**：生成 EditOp → 适配器按 §7.1/§7.2 做 token 替换与风格重放生成新字节 → §7.6 基线校验 → §7.4 原子写 → 成功后更新该 doc 基线（`original_bytes` / `content_hash`）并记入本文件 undo 栈（§7.7）；
5. **提交失败**：磁盘 I/O、权限、rename 失败或基线冲突未决 → 本次 EditOp 退回未提交暂态，并按失败原因分流：基线冲突未决 → 弹出 §7.6 冲突模态等待用户抉择（默认"重新加载"丢弃该文件暂态；"强制覆盖"则保留本次编辑直接写入）；磁盘 I/O、权限等其他失败 → UI 顶部错误条提示并可重试。其他文件的提交不受影响。

提交期校验只针对本次 EditOp；未编辑条目不参与。加载期已存在的 `W-INFER-CONFLICT`（如 §5.2 的 THROW_IN_ADVANCE_MIN_M 反例）只做黄标展示，**不得**在提交期对“本次未编辑的条目”重复告阻（I-6 的推论）。dormant（休眠）条目**允许编辑并实时落盘**：dormant 不属于提交门控的拦截条件，控件持续黄标并提示“当前不生效（休眠配置）”（§10 U-8）；readonly 条目不可编辑，天然不进入提交流程。v0.2 的“diff 预览 + 确认保存”步骤随保存动作一并移除；变更可视化降级为可选的“最近提交回显”（§10 U-7）。

### 7.6 外部修改检测与提交前基线校验

- 打开时计算 `content_hash`（sha256）作为**会话基线**；每次成功提交后基线更新为已落盘字节（§7.5）。
- 打开期间**必须**以固定周期重读文件内容并比对哈希（**纯轮询**，v0.4 决议）：默认周期 **2s**，可经 CLI 参数 `--poll-interval <秒>` 配置（§9.1）；发现外部变化立即在 UI 显示“文件已在磁盘上被修改”横幅；不自动覆盖、不自动重载。操作系统级文件监听（watchdog 类）列为 v1.5 增强，v1 不依赖。网络文件系统（NFS / SSHFS）说明：轮询不依赖事件通知，在网络盘上的检测可靠性不受影响；开销随网络状况浮动，属尽力而为。
- **每次提交写盘前必须再比对一次**（竞态兜底；undo/redo 落盘同样适用）：当前磁盘字节哈希等于会话基线才允许 rename；不一致则**不得**覆盖，弹出冲突模态框：
  - **重新加载**（默认）：丢弃本文件未提交暂态，重新 load 并建立新基线（外部修改不丢失）；该文件 undo/redo 栈同时清空（旧栈条目的写回定位 locator 对新文档无保证），新基线 = 重新加载内容；
  - **强制覆盖**（须显式选择，UI 二次警示将覆盖外部修改）：以本次待写字节覆盖磁盘文件；成功后会话基线更新为本次写入的字节与哈希。**强制覆盖会永久丢失外部修改，且被覆盖的外部内容不在本文件 undo 栈内、不可通过 undo 找回**——二次确认文案必须明示此点。
  - 用户暂不处理（关闭模态）→ 该文件暂停自动提交，顶部错误条常驻提示，暂态保留，待用户重试提交或重载。
- 轮询发现文件**被删除 / 移动 / 权限变更**（不可读）→ 顶部横幅提示（文案区别于“已在磁盘上被修改”横幅），该文件全部条目转入**只读态**（不可编辑、不产生新提交）；文件恢复或用户重载后解除（v0.4 决议）。
- 宿主集成依赖此机制 + 原子写保证“文件即协议”不读到半成品（§9.3）。

### 7.7 撤销 / 重做与退出语义

- 每文件独立 undo/redo 栈，只记录**已提交**编辑；Ctrl+Z 撤销、Ctrl+Shift+Z 重做（§10 U-11）；切换活动文件互不影响。
- 每文件 undo 栈**有界：上限 200 条**已提交编辑，超出淘汰最旧（v0.4 决议）；任一新提交落盘后，该文件的 redo 栈清空。
- undo = 对目标条目施加反向 EditOp 并**立即走完整提交流程**（§7.6 基线校验 + §7.4 原子写）；redo 同理。落盘失败或基线冲突的处理与普通提交一致（§7.5 第 5 步、§7.6）。
- **关闭文件**：关闭入口见 §10 U-12。关闭前若有未提交暂态，先按失焦提交逻辑落盘（§7.5 第 3 步）；暂态非法则弹确认框（放弃暂态并关闭 / 取消关闭）。关闭触发的提交失败时：基线冲突 → 弹 §7.6 冲突模态，抉择完成前不关闭；其他失败（权限、磁盘 I/O 等，暂态按 §7.5 第 5 步退回）→ 错误条提示并阻止关闭，用户可重试或选择"放弃暂态并关闭"（视同"暂态非法"确认路径）。关闭后该文件的基线、未提交暂态、undo/redo 栈与诊断全部释放，不影响其他文件。
- **退出语义**：无"未保存更改"概念。正常退出前**必须** flush：对所有处于防抖等待期的合法暂态立即提交；类型/declared 违规的暂态本就不会落盘，退出即丢弃（UI 应当列出这些条目）。退出完成即保证所有已提交编辑均已落盘。flush 期间逐文件处理异常：撞基线冲突 → 弹 §7.6 冲突模态（重新加载 / 强制覆盖 / **取消退出**，取消则留在应用）；提交失败（权限、磁盘 I/O 等）→ UI 顶部错误条提示并可重试 + 确认框（**仍要退出** = 放弃该文件未提交暂态并退出，exit 3；**取消** = 留在应用）。

## 8. 类型与校验规则

### 8.1 类型判定优先级

```
显式 @type 标注（declared） > 格式自身类型 > 两者皆无（type=None）
```

- **格式自身类型**：python 字面量自带类型（`True`→bool、`10000`→int、`1.85`→float、`"s"`→str）；yaml 按 1.2 core 解析，带引号 → str（`"192.168.10.110:9876"`→str）。金样本中所有可编辑条目都有格式自身类型，`type=None` 仅出现在只读容器条目。
- 格式自身类型**不可被注释推翻**：注释说"这是整数"但字面量是 `1.85` → 以字面量为准。
- 类型一经判定，v1 内不可变（改类型 = 用户手改文件）。

### 8.2 值合法性与硬/软校验

| 校验 | 级别 | 规则 |
|---|---|---|
| 类型匹配 | 硬（拦截） | int 条目不接受 `1.5`、`3.0` 或带引号形式（如 `"3"`）；bool 条目只接受真布尔；float 条目接受整数值输入（规范化为 float 字面量，§7.2）；str 条目接受任意文本（含空串，如 `own_color: ""`） |
| declared range/enum | 硬（拦截） | 违规暂态不落盘，控件红标并说明（展示 @ 标注原文）；declared enum 时取值限定在候选内；range 允许单边界，仅校验存在的一侧（§3.1） |
| inferred range/enum | 软（黄色警告） | 违规不拦截，照常提交落盘并持续黄标（I-6）；枚举候选仅供下拉建议，允许列表外值（YC-6） |

所有校验以“本次提交的 EditOp 集合”为对象（逐条目门控，§7.5）；未编辑条目不参与提交期校验。

数字输入边界（v0.4 决议，§10 U-6）：数字控件**不钳制**（不向范围边界收敛取值），超出 declared 范围 → 红标拦截提交；输入中间态（仅 `-`、空串等）视为非法、不提交；float 接受科学计数法（如 `1.5e3`），按目标格式的数字语法校验，落盘字面量仍按 §7.2 风格重放。

## 9. CLI 与宿主集成契约

### 9.1 命令行

```
configer open <file> [<file> ...] [--format auto|python|yaml]
              [--poll-interval <秒>] [--host <addr>] [--port <n>]
configer --version
configer --help
```

- `open` 是 v1 唯一子命令，接受**一个或多个**路径，全部打开为多文件会话（§3.10、§10 U-2）；`--format` 作用于全部文件。`check` 列为 **v1.5 占位**子命令（v0.4 决议）：只读校验指定文件、输出诊断列表（§3.7），供 CI / 宿主启动前自检；v1 不实现。其他子命令保留。
- 部分文件加载失败**不得**阻断会话：失败文件在侧边栏以诊断态呈现（§10 U-10），stderr 打印诊断摘要；全部失败无法进入 GUI → exit 2。
- `--format` 默认 `auto`；显式指定时嗅探逻辑见 §4.2。
- `--poll-interval <秒>`：外部修改轮询周期（§7.6），默认 2；仅影响检测及时性，不影响提交前基线校验（v0.4 决议）。
- `--host` / `--port`：浏览器模式监听地址与端口的**显式覆盖**参数；默认仅绑定 `127.0.0.1` 随机端口、不默认暴露局域网（§10，v0.4 决议）。
- 参数错误按 exit 2 处理，stderr 输出原因。
- v1 不提供无 GUI 的批处理模式（如 `configer set key value`）；如需要属新契约，须扩展本规范。

### 9.2 退出码

| 码 | 含义 |
|---|---|
| 0 | 正常退出：所有已提交编辑均已落盘（实时落盘模型无“未保存”概念，§7.7）；单实例转交完成后第二进程亦以 0 退出（未发生写盘，§9.4） |
| 1 | 启动阶段取消（未进入 GUI 会话），未发生任何写盘。实时模型下不存在"放弃修改"的退出路径（§7.7） |
| 2 | 加载失败：文件不存在/不可读、非 UTF-8（`E-ENCODING`）、格式无法识别（`E-FORMAT`）、解析失败（`E-PARSE*`）、命令行参数错误 |
| 3 | 落盘失败：磁盘 I/O、临时文件/rename 失败、退出 flush 被用户放弃等（§7.7） |
| ≥4 | 保留，v1 不得使用 |

加载失败时若无法进入 GUI，**必须**在 stderr 打印诊断摘要（code + message）。

### 9.3 宿主集成模式（文件即协议）

宿主以子进程调用 `configer open <file>`，随后二选一：

- **模式 A（监听）**：宿主监听文件变化（inotify 或 mtime+哈希轮询），变化即重读配置，热生效；
- **模式 B（退出后重读）**：宿主等待子进程退出后重读一次（实时落盘下中途重读亦安全，语义同模式 A 的单次触发）。

configer 侧保证（宿主可依赖的契约）：

- **GR-1** 只在本会话提交（用户编辑 / undo / redo）时写文件（§7.5、§7.7），且每次写盘前做基线校验（§7.6）；盘上始终是最后一个合法状态；
- **GR-2** 写入是原子的（rename），监听方不会读到半成品；
- **GR-3** 退出码 1 时未发生任何写盘（§9.2）；
- **GR-4** 退出码语义稳定（§9.2）；
- 外部并发写由 §7.6 的哈希检测 + 提交前基线校验 + 冲突模态兜底；宿主在 configer 运行期间**不应当**并发写同一文件；实时落盘下写盘频率高于保存制，模式 A 监听方**应当**对重读做合并/防抖（§13 K-9）。

### 9.4 单实例与转交（v0.4）

configer 启动时**必须**通过本地 socket / 锁文件检测是否已有同一用户的活动实例：

- **无活动实例** → 正常启动，并登记本地 socket / 锁文件；
- **有活动实例** → 与其握手并把本次 CLI 的文件清单转交（路径规范化后逐个处理：对方未打开的加入其侧栏并激活，已打开的仅聚焦），转交成功后本进程以 exit 0 退出（未发生任何写盘，§9.2；UI 侧见 §10 U-13）；
- **陈旧锁文件**（登记存在但握手失败，如上次进程崩溃残留）→ 清理该锁文件后自行正常启动。

转交通信仅限本机、同一用户；转交握手失败一律按陈旧锁文件兜底（清理并自行启动），**不得**阻塞用户打开文件（§13 K-11）。

## 10. UI 需求概述

本章只定需求（U-n），不定实现细节。GUI 技术栈已决议（2026-09-08）：**NiceGUI 双模式**——开发与 M2 验收用**浏览器模式**（NiceGUI 默认 `ui.run()`，本地端口打开），桌面窗口形态用 **native 模式**（`ui.run(native=True)`，底座 pywebview），两种模式前端代码完全相同；决议理由与备选见附录 B。UI 布局与编辑模型亦已决议（2026-09-08）：**IDE 形态**（左侧多文件侧边栏 + 右侧条目主区，参考 ZCode）与**实时落盘**（无保存动作，§7.5）。v0.4 追加决议：**界面文案统一为简体中文**（诊断 message 本就为中文，§3.7）；浏览器模式默认仅绑定 `127.0.0.1` 随机端口、**不默认暴露局域网**，远程场景（如编辑机器人上的配置）统一走 SSH 端口转发，`--host` / `--port` 为显式覆盖参数（§9.1）；**会话持久化**（记忆最近文件 / 布局）v1 不做，列 v1.5 候选；主区布局细节（条目列表 / 说明面板排布、分组折叠默认态等）按 NiceGUI 惯例、M2 实现期定，不属本规范强制。以下为 v1 必须满足项：

- **U-1 IDE 布局与侧边栏**：左侧为文件侧边栏，右侧为主区。侧边栏可收起/弹出：工具栏 toggle 按钮 + 快捷键 Ctrl+B；收起后主区占满整宽；侧边栏与主区分隔条可拖拽调整宽度。
- **U-2 多文件会话**：侧边栏列出**所有已打开**的 config 文件。打开途径：CLI 一次传入多个路径（§9.1）、会话内"+"按钮新开、拖拽文件入窗口。每项显示文件名（悬停 tooltip 显示完整路径）、格式徽标（python/yaml）、加载诊断状态指示（§3.7 有无 error/warning）；活动文件高亮，点击切换，主区随之显示该文件内容（每文件一个 ConfigDoc，§3.10）。
- **U-3 条目列表**：主区按 分组/子分组 折叠展示**活动文件**的条目（短名 + 类型标识）；顶部搜索框按路径与说明文本子串过滤并高亮。
- **U-4 详情面板**：展示选中条目的说明全文——python 按 作用/影响/建议 分段（含前导段与原文），yaml 展示行尾注释原文；dormant/warning 标记展示原文依据；readonly 展示原因；单位（unit）与默认值（如有 @default）展示。
- **U-5 推测徽标**：所有 inferred 约束与候选带"推测"字样（C-1/I-7）。
- **U-6 类型控件映射与门控反馈**：bool→复选框；int/float→数字输入（有 range 时显示范围提示）；str→单行文本框；存在枚举候选→下拉框（inferred 候选仍允许自定义输入，YC-6；declared 候选限列表内）。控件即时反馈门控结果（§7.5）：类型/declared 违规 → 红标 + 原因（不落盘）；inferred 违规 → 黄标（照常落盘，持续黄标）。数字输入不钳制，超 declared 范围红标拦截；中间态（`-`、空串）视为非法不提交；int 不接受 `3.0` / 带引号形式；float 接受科学计数法（§8.2，v0.4）。
- **U-7 实时提交与撤销**：无保存按钮、无 diff 预览步骤——合法暂态按控件分型自动提交落盘（点击类即时、文本类 400ms 防抖、失焦立即，§7.5）；提交失败在 UI 顶部错误条提示并可重试；每文件独立 undo/redo：Ctrl+Z / Ctrl+Shift+Z，undo 栈每文件上限 200 条（§7.7）。可选增强（非必须）：“最近提交回显”（如在状态栏短暂显示 `step_interval: 100. → 1920.`）。
- **U-8 状态标志展示与编辑语义（v0.4 改写）**：readonly 条目灰显禁改；dormant 条目**允许编辑并实时落盘**，控件持续黄标并提示“当前不生效（休眠配置）”（不属于提交门控拦截条件，§7.5）；warning 条目黄标；三类条目均可见可选中、可查看说明。
- **U-9 外部修改横幅与冲突模态**：§7.6 的检测横幅与冲突模态框（默认"重新加载"）。
- **U-10 加载失败态**：加载失败的文件在侧边栏以诊断态标示，主区展示诊断列表（code + message），不白屏，且不影响其他已打开文件。加载成功但带 **warning 级诊断**的文件：侧栏文件项显示**黄色徽标**，点开可在主区查看该文件的诊断列表（code + message），不阻塞编辑（v0.4 决议）。
- **U-11 键盘操作**（应当）：上下条目导航、Ctrl+B 侧栏开合、Ctrl+W 关闭当前文件（U-12）、Ctrl+Z / Ctrl+Shift+Z 撤销/重做（作用于活动文件）。
- **U-12 关闭文件**：侧栏文件项提供关闭入口（悬停 × / 右键菜单 / Ctrl+W）；关闭前若有未提交暂态，先按失焦提交逻辑落盘（§7.5 第 3 步），暂态非法则弹确认框（放弃暂态并关闭 / 取消关闭）；提交失败按 §7.7 分流处理（基线冲突模态未决前不关闭；其他失败阻止关闭，可重试或放弃暂态关闭）；关闭后该文件的基线、未提交暂态、undo/redo 栈与诊断全部释放（§7.7）。
- **U-13 单实例转交（v0.4）**：重复执行 `configer open` 时，文件清单转交给已有实例——未打开的加入其侧栏并激活、已打开的仅聚焦，第二进程随即 exit 0 退出；陈旧锁文件（握手失败）自动清理并正常启动（§9.4）。

- **A-7 推测范围 ≥5**：至少 5 个 `建议: [a, b]` 正确转为范围约束并标"推测"（如 `KICK_POWER_MIN`[1.0,2.0]、`ARRIVE_DIST`[0.05,0.30]、`MAX_LINEAR`[1.0,2.0]、`GOALIE_MAX_Y_OFFSET`[0.5,1.3]、`FALLEN_COST`[5,50]）；`KICK_EXIT_M` 的增量式 `KICK_ENTER_M + [0.2, 0.6]` 与 `CENTRE_KICKOFF_ANGLE_STEP_DEG` 的 `±[1, 5]` **不得**产生范围（P-6 负向用例）。
- **A-8 现值冲突警告**：加载期对 `THROW_IN_ADVANCE_MIN_M`（-2.0 ∉ [1.5,3.0]）与 `CORNER_KICK_POWER`（1.6 ∉ [3.0,8.0]）各产生一条 `W-INFER-CONFLICT` 黄色警告；提交其他条目时这两条**不阻塞**；`KICK_ENTER_M`（1.4，注释写"保持 1.2"）**不得**产生警告（P-10 负向用例）。
- **A-9 校验分级与不落盘**：把某 int 条目改成非整数 → 控件红标并展示原因，防抖窗口后磁盘字节**不变**（硬校验，§7.5）；把 `ARRIVE_DIST` 改到 [0.05,0.30] 之外 → 黄色警告、照常提交落盘且持续黄标（I-6）。
- **A-10 CLI 契约**：`--format yaml` 打开 .py 文件 → exit 2 且 stderr 含诊断；`configer open param.py config.yaml` 两文件同时入会话并可独立切换编辑（U-2）；正常退出码 0，退出时所有已提交编辑均已落盘（§9.2）。
- **A-11 外部修改**：打开期间于磁盘改文件 → 出现横幅；随后任一次提交因基线校验失败被阻止 → 冲突模态（默认"重新加载"，丢弃该文件未提交暂态）；选重载后外部修改完整保留，全程不被 configer 覆盖（§7.6）。
- **A-12 侧栏与多文件行为**：Ctrl+B / 工具栏按钮收起侧栏（主区占满）再展开；分隔条拖拽调宽生效；侧栏项含文件名、格式徽标、诊断指示，悬停 tooltip 为完整路径；活动文件高亮，点击切换后主区与 undo 栈随之切换；"+"按钮与拖拽打开均产生新侧栏项（U-1、U-2）。
- **A-13 提交时机与失焦提交**：点击类控件（bool / 枚举下拉）值变化**即时**落盘（`git diff` 出现目标行）；文本类（int/float/str）在最后键击 **400ms** 后自动落盘；失焦（含切换 / 关闭活动文件）立即提交；防抖窗口内连续输入合并为最后一次提交（§7.5）。
- **A-14 撤销 / 重做落盘**：对已提交编辑 Ctrl+Z → `git diff` 该行恢复原字面量（反向编辑已落盘）；Ctrl+Shift+Z → 恢复新值；各文件栈相互独立，切换活动文件后撤销作用于活动文件（§7.7）。
- **A-15 退出 flush 与提交失败**：编辑后立即退出（尚处防抖窗口内）→ 退出前 flush，最后编辑已落盘（§7.7）；模拟落盘失败（如目标目录只读）→ 错误条提示并可重试 + 确认框：仍要退出 = 放弃该文件暂态并 exit 3，取消 = 留在应用（§7.7、§9.2）。
- **A-16 关闭文件**：有未提交合法暂态时关闭 → 暂态先落盘再关闭（`git diff` 出现目标行）；暂态非法 → 确认框可选"放弃暂态并关闭"；关闭后该文件基线、undo/redo 栈与诊断释放，其他文件的编辑与 undo 不受影响；关闭中提交失败 → 基线冲突弹 §7.6 冲突模态且未决前不关闭，其他失败（如目录只读）→ 阻止关闭、错误条可重试，可放弃暂态后关闭（§7.7、U-12）。

已决议（不再列为开放问题）：

- **GUI 技术栈（2026-09-08 决议）**：采用 **NiceGUI 双模式**——
  - 开发与 M2 验收用**浏览器模式**：NiceGUI 默认 `ui.run()`，本地端口打开，零分发成本；
  - 桌面窗口形态用 **native 模式**：`ui.run(native=True)`（底座为 pywebview，Linux 依赖 GTK 绑定），两种模式前端代码完全相同、一行不改；

  - 选型理由：① 与 Python 核心（libcst / ruamel.yaml）同进程，纯 Python 单语言，无 IPC 序列化层；② 浏览器模式免费获得"远程编辑"能力——宿主配置文件常在远端机器（如机器人 / Jetson）上，笔记本浏览器经端口转发 / 局域网即可编辑；③ 迭代最快，未来如需最小包体单文件分发，前端逻辑可迁往 Tauri 壳，路径不封死。
  - 备选（记录但不采用）：PySide6（如需纯原生控件风格）、Tauri 2 + Python sidecar（如未来对包体 / 启动速度有硬指标）。
  - 移动端明确为非目标（§1.2 第 7 条）；"远程改配置"场景由浏览器模式覆盖。
- **UI 布局（2026-09-08 决议）**：IDE 形态——左侧可收起的多文件侧边栏（工具栏 toggle + Ctrl+B）+ 右侧条目主区，细则见 §10（U-1/U-2）。
- **编辑模型（2026-09-08 决议）**：实时落盘，取消“保存”动作；编辑生命周期、提交门控、提交前基线校验、undo 落盘与退出 flush 见 §7.5–§7.7。
